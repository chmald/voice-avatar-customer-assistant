# 07 — Azure vs on-prem responsibility matrix

> Engineering reference for **what stays integrated with Azure** vs **what
> runs on the on-prem edge host** in each mode. Use this to brief stakeholders,
> draft network firewall rules, and answer compliance / data-residency
> questions.

| 14 | Image pulls (initial setup only) | n/a | ✅ MCR (`mcr.microsoft.com`) | MCR |

## 2. Network egress and inbound

### What MUST be reachable from the edge host (outbound HTTPS)

| Target | When | Why |
|---|---|---|
| `<foundry>.services.ai.azure.com` | Cloud mode | Voice Live API WebSocket |
| `<foundry>.cognitiveservices.azure.com` | Cloud + Local (connected) | Speech container metering + Voice Live optional REST surfaces |
| `login.microsoftonline.com` | Cloud + Local (connected) | Entra ID tokens for `DefaultAzureCredential` and container metering |
| `mcr.microsoft.com` | Initial setup + container updates | Image pulls; not required at runtime in disconnected mode |
| `huggingface.co` / `*.foundry.microsoft.com` | Initial setup of Foundry Local | Model download; not required at runtime after model is cached |

### What is NEVER required

- Inbound from the public internet to the app or any container.
- Outbound to third-party LLM providers (we don't call OpenAI/Anthropic directly).

### Disconnected (offline-tolerant) deviations

- Replace **runtime** Foundry-resource-key metering with a **license file** generated by `DownloadLicense=True` (renew every ~30 days). See [`../03-deployment.md §5.4`](../03-deployment.md#54-switch-container-metering-to-disconnected-offline-tolerant-sites).
- Foundry Local has no metering — fully offline after model cache is warm.
- The cloud mode still needs all the outbound URLs above; only the **local-fallback path** can run with zero internet once the disconnected license is in place.

## 3. Data flow per mode

### Cloud mode (default)

```
mic ──base64 PCM16──▶ App ──WebSocket──▶ Azure Voice Live ──▶ Avatar Service
                                                          ──▶ HD/Std voices
                                                          ──▶ gpt-realtime LLM
              audio + transcripts ◀── Voice Live ◀── (same events)
              video frames        ◀── Avatar Service via WebRTC
```

Audio crosses the public internet. Data residency = the region of the Foundry resource.

### Local-fallback mode

```
mic ──base64 PCM16──▶ App (edge host) ──HTTP──▶ Speech STT container (loopback)
                                          ──HTTP──▶ Foundry Local (loopback)
                                          ──HTTP──▶ NTTS container (loopback)
              audio + transcripts ◀── App ◀── (assembled locally)
```

Audio never leaves the edge host. Outbound network traffic during a session: **zero** (connected metering uses a periodic background ping, not per-request).

## 4. Where each secret / credential lives

| Secret | Used by | Stored where (production) |
|---|---|---|
| Foundry resource key (KEY1/KEY2) | Speech containers — `ApiKey=...` env var | Site-local secrets manager / Docker secrets / `.env` file with 0600 perms; rotated via Foundry portal. |
| Entra ID token | App (`DefaultAzureCredential`) for Voice Live calls | Acquired on demand; cached in process. Use **managed identity** (or workload identity in K8s) — not a checked-in key. |
| Foundry Local | none | Foundry Local doesn't authenticate; bind it to loopback or to a LAN interface behind a firewall. |
| Speech disconnected license file | Speech containers — bind-mounted as `/license` | Same edge host; back this up. |

## 5. Failure-mode summary

| Failure | Cloud mode | Local-fallback mode |
|---|---|---|
| Internet drops | All sessions fail with `session_error` (unchanged from `main`) | Existing sessions continue (no Azure dependency mid-session); new sessions still work if connected metering grace window holds, or if disconnected license is mounted |
| Foundry resource paused / over quota | Cloud sessions fail; supervisor still marks cloud reachable (TCP succeeds); next session may also fail | Unaffected — uses no Azure resource for inference |
| MCR unreachable | No effect on running containers | No effect; only blocks fresh image pulls |
| Foundry Local crashes | n/a | Local sessions fail until the service is restarted; cloud mode is unaffected |
| One Speech container OOM-killed | n/a | The half it owns fails (STT or TTS). Other half still works; consider raising `mem_limit` in `docker-compose.local.yml` |
| Edge host loses power | All sessions on it fail | Same |

## 6. Quick answer to common questions

> *Does user audio leave the site in local-fallback mode?*
> **No.** Audio is processed entirely on the edge host. Connected-mode container metering sends usage counts (not audio) to Azure on a schedule.

> *Can we run the avatar on-prem?*
> **No.** Microsoft does not publish the real-time TTS Avatar as a container or SDK. Avatar = Azure-only. Local mode is voice-only by design.

> *Can we run `gpt-realtime` on-prem?*
> **No.** `gpt-realtime`, `gpt-realtime-2`, `gpt-realtime-1.5` are Azure-only models. On-prem we substitute a chat-completion LLM via Foundry Local. See [`model-selection.md`](./model-selection.md).

> *Do HD/Dragon voices work on-prem?*
> **No.** Dragon HD voices are not in the Speech container catalog. The local NTTS container ships standard neural voices only.

> *Do we still need to pay for Azure when running mostly offline?*
> **Yes.** The Foundry resource exists for cloud Voice Live (when reachable) and for Speech container metering / license issuance. Disconnected operation uses a **commitment-tier** SKU separate from PAYG.

> *Can the supervisor cause a mid-session switch?*
> **No** (MVP). Routing is per-session. A cloud-mode session that loses connectivity mid-call ends with `session_error`; the **next** session opens in local mode automatically.
